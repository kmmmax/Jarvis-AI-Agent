JARVIS AI AGENT

ИИ-ассистент с поддержкой локальных нейросетей (через Ollama), памятью диалога
и набором инструментов (функций) для взаимодействия с внешним миром и файловой системой.

======================================================================
УСТАНОВКА И ЗАПУСК
======================================================================

1. Скопировать директорию проекта в нужное место и зайти в нее: 
   git clone https://github.com/kmmmax/Jarvis-AI-Agent/
   cd Jarvis-AI-Agent
2. Создать в директории проекта (Jarvis-AI-Agent) рядом с main.py виртуальное окружение и активировать его:
   python -m venv .venv
   source .venv/bin/activate  (Для macOS/Linux)
3. Установить зависимости:
   pip install -r requirements.txt
4. Создать файл .env рядом с main.py и положить в него все необходимые значения:

   Ниже — полный шаблон. Обязательные параметры нужно заполнить, опциональные — по желанию.

   # --- Подключение к Ollama ---
   OLLAMA_HOST=https://kmmax.pp.ru/ollama/      # обязательно
   OLLAMA_USER=ваш_логин                        # опционально
   OLLAMA_PASSWORD=ваш_пароль                   # опционально

   # --- Модель ---
   MODEL=gemma4:e4b-mlx                         # обязательно
   MODEL_ID=google/gemma-4-E4B-it               # обязательно

   # --- Контекст и лимиты ---
   TOKEN_LIMIT=16384                            # обязательно
   MAX_TOOL_ITERATIONS=40                       # обязательно
   CHAT_SERVICE_TOKENS_RESERVE=500              # обязательно
   GENERATE_SERVICE_TOKENS_RESERVE=200          # обязательно

   # --- Локация ---
   DEFAULT_TIMEZONE=Europe/Moscow               # обязательно
   DEFAULT_CITY=moscow                          # обязательно

   # --- Прокси (если вы в России) ---
   PROXY_PROTOCOL=http                          # опционально
   PROXY_URL=http://192.168.88.250:10808        # опционально

   Если прокси не нужен — просто удалите или закомментируйте
   последние две строки.

5. Запустить ассистента:
   .venv/bin/python main.py

======================================================================
ВАЖНО: ПРОКСИ ДЛЯ РАБОТЫ ПОГОДЫ (ЕСЛИ ВЫ В РОССИИ)
======================================================================

Если вы находитесь в России, сервера, с которых API погоды (wttr.in)
собирает данные, могут быть заблокированы или работать нестабильно.
Для корректной работы инструмента get_weather рекомендуется
использовать прокси.

Как настроить прокси:
В файле .env (рядом с main.py) задайте две переменные:
   PROXY_PROTOCOL=http
   PROXY_URL=http://IP_АДРЕС:ПОРТ

Если прокси не нужен — просто удалите или закомментируйте эти строки.

(Если прокси SOCKS5, используйте socks5://... и убедитесь, что
установлена библиотека requests[socks]).

======================================================================
ДОСТУПНЫЕ ИНСТРУМЕНТЫ (ФУНКЦИИ)
======================================================================

Ассистент умеет не только вести диалог, но и выполнять действия.
Вот что он умеет:

   1. get_current_time
      Что делает: возвращает текущее время и дату в указанном часовом поясе.
      Параметры:
         - timezone (опционально): часовой пояс в формате IANA
           (например, Europe/Moscow, America/New_York). Если не указан —
           используется системная таймзона компьютера. Если её не удаётся
           определить — дефолтная таймзона (DEFAULT_TIMEZONE из .env).
      Особенности: умеет определять локальную таймзону автоматически
      (через библиотеку tzlocal).

   2. get_weather
      Что делает: узнаёт текущую погоду и прогноз максимальной температуры
      на сегодня.
      Параметры:
         - city_name (опционально): название города на английском
           (например, Moscow, London). Если не указан — используется
           DEFAULT_CITY из .env.
      Особенности: работает через wttr.in. Если вы в России, обязательно
      настройте прокси (см. раздел выше), иначе запрос может зависнуть.

   3. list_dir
      Что делает: показывает список файлов и папок в указанной директории.
      Параметры:
         - dir_path (опционально): путь к папке (например, ., tools,
           /home/user). По умолчанию — текущая папка.
         - limit (опционально): максимальное количество элементов
           для вывода (по умолчанию 50).
      Особенности: сначала выводит папки, потом файлы. Если элементов
      больше лимита — предупреждает и показывает, сколько скрыто.

   4. read_file_content
      Что делает: читает и возвращает текстовое содержимое файла.
      Параметры:
         - file_path (обязательно): путь к файлу (например, main.py,
           system_prompt.txt).
         - limit_of_chars (опционально): сколько символов прочитать
           за один раз (по умолчанию 5000).
         - offset (опционально): с какого символа начать чтение
           (по умолчанию 0).
      Особенности:
         - Если файл больше лимита — выводит предупреждение [ALERT]
           и указывает, какой offset передать в следующий раз, чтобы
           дочитать.
         - Не читает бинарные файлы (картинки, архивы).
         - Защищён от чтения огромных файлов, чтобы не переполнить
           контекст нейросети.

======================================================================
УПРАВЛЕНИЕ КОНТЕКСТОМ (ПАМЯТЬ)
======================================================================

Нейросеть не может запомнить бесконечно много текста. У ассистента есть
защита от переполнения:

   - Лимит токенов: TOKEN_LIMIT из .env (по умолчанию 16384).
     Значение читается через config.py и также передаётся в Ollama
     через options={"num_ctx": ...} в запросах chat и generate,
     чтобы модель реально использовала это окно, а не дефолтные 4K.

   - Автоматическая обрезка: если история диалога становится слишком
     длинной, старые сообщения удаляются целиком (парами «вопрос-ответ»),
     чтобы освободить место. Системный промпт при этом сохраняется.

   - Аварийный сброс: если даже последний вопрос + результаты инструментов
     не влезают в лимит, история сбрасывается до системного промпта
     и текущего запроса. Ассистент предупредит вас об этом красным текстом.

======================================================================
РЕЖИМЫ РАБОТЫ
======================================================================
   
   1. Chat (Режим чата)
      Бесконечный цикл с сохранением истории. Ассистент помнит, о чём вы
      говорили ранее, и может использовать инструменты.

   2. Generate (Режим генерации)
      Один запрос — один ответ. Без памяти и без использования инструментов.
      Подходит для простых вопросов.

   Для выхода из программы введите exit, stop или нажмите Ctrl+C.
